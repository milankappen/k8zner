# WP-001 — CRD codegen infrastructure

Lane A · Depends on: — · Blocks: WP-002, WP-101, WP-102, WP-202

## Goal

Make adding/changing CRDs a reproducible, CI-guarded operation. Today deepcopy and
CRD YAML were generated ad-hoc by hand-run controller-gen; there is no `make
generate`, no pinned tool, and the sync targets hardcode a single CRD filename.
Every CRD-touching WP depends on this being fixed first.

## Context & anchors

- `api/v1alpha1/groupversion_info.go` — group `k8zner.io`, `SchemeBuilder`,
  `init()` with `SchemeBuilder.Register(&K8znerCluster{}, &K8znerClusterList{})`.
- `api/v1alpha1/zz_generated.deepcopy.go` — generated by controller-gen; the CRD
  YAML annotation `controller-gen.kubebuilder.io/version: v0.20.0` is the only
  version pin in the repo.
- CRD YAML exists in 3 places: `config/crd/bases/k8zner.io_k8znerclusters.yaml`
  (canonical), `deploy/crds/`, `internal/addons/operator-chart/crds/`.
- `Makefile:101–113` — `sync-crds` / `check-crds` literally `cp`/`diff` the one
  hardcoded filename.
- `.github/workflows/ci.yaml` — `check-crds` is currently NOT wired into CI.

## Contract

- `make generate` regenerates deepcopy; `make manifests` regenerates CRD YAML into
  `config/crd/bases/`; both use a **pinned** controller-gen (v0.20.0 or a
  deliberate, documented upgrade), installed on demand into `bin/` (no global
  install requirement) — follow the existing `setup-envtest` target style.
- `sync-crds` / `check-crds` handle **all** files in `config/crd/bases/` (glob, not
  a hardcoded name), syncing to both downstream locations.
- CI fails when generated code is stale: a job (or step in `lint`) runs
  `make generate manifests && git diff --exit-code` plus `make check-crds`.
- Running the targets on the current tree is a no-op diff (proves determinism).

## Non-goals

- No new CRDs (that's WP-101/102/202). No changes to existing CRD schemas.
- No conversion webhooks / multi-version support.

## Acceptance criteria

1. `make generate manifests` twice in a row → `git status` clean both times.
2. Delete `zz_generated.deepcopy.go`, run `make generate` → file restored identical.
3. Touch a field comment in `types.go`, run `make manifests` → only the canonical
   CRD YAML changes; `make sync-crds` propagates to both copies; `make check-crds`
   passes; revert.
4. CI: a PR with hand-edited generated output fails the new check.

## Hints

- Pattern for tool pinning: `ENVTEST_K8S_VERSION` + `setup-envtest` in the Makefile.
  `go run sigs.k8s.io/controller-tools/cmd/controller-gen@v0.20.0` also works and
  avoids a bin-management step — either is fine; document the choice in the
  Makefile help text.
- Keep the kind-cluster CRD copy path in mind: `tests/kind/` applies CRDs from the
  chart; nothing there should need changes if sync stays correct.
